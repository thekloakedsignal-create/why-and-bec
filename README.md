# YN — the Why & Because game 🎉

A real-time multiplayer party game for **3–5 players**, playable entirely in the browser.

Each round:

1. Everyone writes a **WHY** question.
2. Questions pass **one seat clockwise** around a fixed player circle.
3. Everyone answers the question they received with a **BECAUSE** — without knowing who asked.
4. All WHY + BECAUSE combos are revealed.
5. Everyone votes for the funniest BECAUSE (**you can't vote for your own**).
6. The top-voted answer wins its author a point. **Ties share the win.**

Multiple rounds, a live leaderboard, and a final champion. Built with Node.js, Express, and Socket.IO — no build step, no database.

---

## Quick start (local dev)

```bash
npm install
npm start
# open http://localhost:3000
```

Play testing by yourself? Open 3 tabs and use the **nickname login** — rooms need at least 3 players.

Set `npm run dev` for auto-restart on file changes.

Environment variables are optional for local dev. Copy `.env.example` to `.env` if you want to configure X login or AI locally.

## Deploying to Render

This repo is ready to go as either a **Blueprint** (uses `render.yaml`) or a plain **Web Service**.

### Option A — Blueprint (recommended)

1. Push this repo to GitHub.
2. In Render: **New → Blueprint**, pick the repo.
3. Render reads `render.yaml` and creates the web service (free plan, health check on `/healthz`, `SESSION_SECRET` auto-generated).
4. Deploy. Your game is live at `https://<your-service>.onrender.com`.

### Option B — Manual Web Service

1. **New → Web Service**, pick the repo.
2. Runtime: **Node**. Build command: `npm install`. Start command: `node server.js`.
3. Add a `SESSION_SECRET` env var (any long random string).
4. Deploy.

## Setting up real X sign-in (do this after first deploy)

Until you add credentials, the game offers a **nickname login** so it's fully playable.

1. Go to **developer.x.com** → create a **Project & App** (free tier works).
2. In your app settings, enable **OAuth 2.0** with:
   - **Type of App:** Web App
   - **Callback URI:** `https://<your-service>.onrender.com/auth/x/callback` — must match exactly, including https.
   - **Website URL:** `https://<your-service>.onrender.com`
3. Copy the **Client ID** and **Client Secret**.
4. In Render → your service → **Environment**, add:
   - `X_CLIENT_ID` = your client id
   - `X_CLIENT_SECRET` = your client secret
   - `X_CALLBACK_URL` = `https://<your-service>.onrender.com/auth/x/callback`
5. Save (Render redeploys). The nickname login disappears and **Sign in with X** appears.

The game only requests read-only profile scopes (`tweet.read users.read offline.access`) to get the player's name, handle, and avatar.

## Optional: xAI "Inspire me" button

Players can ask Grok for a funny WHY idea during the question phase. **The game is fully playable without it** — with no key set, the button simply doesn't appear.

1. Get a key at **console.x.ai**.
2. In Render → **Environment**, add:
   - `XAI_API_KEY` = your key
   - `XAI_MODEL` = `grok-3-mini` (default; any chat model works)
3. Save and redeploy.

> ⚠️ Never commit API keys to the repo. `.env` is git-ignored; keys live only in Render's env vars or your local `.env`. If a key is ever exposed publicly (chat, screenshots, commits), **revoke it at console.x.ai and generate a new one**.

## Configuration reference

| Variable          | Required | Purpose                                                |
| ----------------- | -------- | ------------------------------------------------------ |
| `SESSION_SECRET`  | Yes (prod) | Signs session cookies. Auto-generated by Blueprint.  |
| `X_CLIENT_ID` / `X_CLIENT_SECRET` / `X_CALLBACK_URL` | No | Enables real X sign-in. All three together or none. |
| `XAI_API_KEY` / `XAI_MODEL` | No | Enables the AI idea button.                     |
| `ALLOW_DEV_LOGIN` | No       | `true` keeps nickname login alongside X login.         |
| `PORT`            | No       | Render sets this automatically (default 3000).         |

## Game / tech notes

- **Rooms** are 4-letter codes; share the code, friends join from the same URL.
- The **player circle** is shuffled once per game at game start and stays fixed; questions always rotate exactly one seat clockwise per round.
- Scoring, self-vote blocking, timers, and rotation are all **server-authoritative**.
- Players who disconnect can **rejoin mid-game** with the same room code; phases auto-advance when remaining connected players finish, and rooms collapse to the lobby if too few players remain.
- State lives **in memory** — restarting the service clears active rooms (fine for party games; the free Render tier also sleeps when idle).
- Hosts pick the round count (1–8, default 3). Host migrates automatically if the host disconnects.
